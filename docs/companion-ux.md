# 陪伴交互规格

2026-10-11；对应第二阶段 P1、S02。
**状态：设计草案，待所有者审阅。** 本文供后续 Goal B 使用，
本次 Goal A 不在正式 App 实现“我们”页、小组或共享，不添加演示成员和演示记录。
核心原则：不排名、不催促、不替人打卡；各自目标独立，分享始终出于本人选择。

## 入口与三种状态

个人“今天”、回顾与提醒始终独立可用；登录和组队都不是使用门槛。
Goal B 启动并实现后才加入“我们”入口，不提前放入不可用的正式页面。

| 状态 | “我们”的内容 | 可操作项 | 不出现的内容 |
| --- | --- | --- | --- |
| 未登录 | 克制的空状态：“和熟悉的人分享近况” | 登录；返回今天 | 假成员、完成率、反复弹出的邀请提醒 |
| 已登录、无小组 | “还没有加入小组” | 创建私密小组；输入邀请；返回今天 | 大面积广告式组队引导、对个人功能的限制 |
| 已加入小组 | 获准成员的共享目标、授权进度和各自发布的文字近况 | 查看共享项；本人管理共享；独立发布近况；回复 | 未共享目标、私人备注、成员排名、缺席名单、替人打卡 |

已加入状态按成员分区，但不按完成率、打卡天数或活跃度排序。
不同成员的目标、频率和数量可以完全不同，不显示用于互相比较的汇总比例。
首屏优先可读的授权内容；只加载到一部分时明确表达，不用 0% 代替未加载。

## 按目标共享

流程：个人目标详情 → 共享设置 → 选择小组和拟公开范围 →
确认实际可见字段 → 服务端授权成功 → 在“我们”显示。

- 新建目标默认私密；登录、创建小组、加入小组都不会批量开启共享。
- 选择界面列出自己的目标和独立开关；每项默认关闭。
- 确认前展示具体标题、执行规则与准备公开的进度，不混入私人备注或未选目标。
- 第一份草案只分享生效后的授权进度；既有历史如何展示仍待 Goal B 决定，
  未确认前不默认向新成员开放历史。
- 分享状态区分未共享、提交中、已共享、修改失败。离线点击不能显示“对方已可见”。
- 取消操作不改变本人的目标、打卡或提醒；共享只是额外授权关系。

撤销流程：目标共享设置 → “停止共享” → 确认 →
服务端撤销 → 其他成员后续请求被拒，客户端获知后移除缓存。
失败时保留“尚未确认停止共享，可重试”，不只关闭本机开关。
撤销不能追回已经看过、截图或自行保存的内容，确认文案明确说明。

## 创建、邀请、加入、退出

| 流程 | 状态和行为 | 隐私要求 |
| --- | --- | --- |
| 创建 | 填小组名称 → 创建中 → 成功/可重试失败 | 创建后仍没有任何已共享目标 |
| 邀请 | 发起受控邀请 → 展示可分享的邀请信息 → 复制/由用户主动发送 | 不读通讯录，不自动发送；有效期与使用次数由 Goal B 确认 |
| 加入 | 输入或打开邀请 → 验证 → 加入确认 → 成功/无效/已失效/网络失败 | 无效邀请不给出成员身份；加入不读取对方私密目标、不自动共享本人目标 |
| 重复加入 | 已是成员则显示已有小组 | 幂等，不增加重复成员或扩大权限 |
| 退出 | 小组设置 → 说明访问变化 → 确认 → 服务端退出事务 | 保留本人的目标、历史、提醒；撤销该小组的访问与清理受限缓存 |
| 退出失败 | “尚未确认退出，请联网后重试” | 不把本机隐藏小组当作服务端已撤权 |

退出确认文案草案：
“退出后，你将无法再查看这个小组的共享内容。你的个人目标、记录和提醒仍会保留。”
既有动态、回复的留存方式尚未确定，Goal B 必须补上明确规则后才开放真实用户。
管理员转交、最后一人退出、小组解散和邀请上限也保持待决定，不由本草案暗中定案。

## 可见范围

| 数据 | 本人 | 获授权的同组成员 | 非成员/未登录 |
| --- | --- | --- | --- |
| 私密目标和打卡 | 可管理 | 不可访问 | 不可访问 |
| 共享目标及授权进度 | 可管理/撤销 | 只读授权字段 | 不可访问 |
| 私人备注、无关目标、未授权历史 | 可管理 | 不可访问 | 不可访问 |
| 本人公开给小组的文字近况 | 可发布和按后续规则管理 | 可读与回应 | 不可访问 |
| 他人的目标和打卡写入 | 不适用 | 不允许，即便是管理员 | 不允许 |
| 对方私人目标的数量、名称或汇总 | 本人可见 | 不可由统计或提示间接获知 | 不可访问 |

所有规则都须由服务端认证、RLS/受控函数执行，并以直接接口测试验证。
不接受“页面没有入口”作为授权证据。成员退出、撤销共享和账号切换均清理受限缓存。

## 打卡、表达与提醒

- 完成是个人事实；发近况是独立表达。两者不能捆绑提交。
- 未完成也能说“今天调整了安排”；完成后不强制发动态。
- 回应使用普通文字与轻量鼓励，不形成分数、连续关系天数或成就排名。
- 个人提醒只由本人设置，不自动转换为提醒对方的通知。
- 没有记录只展示“暂无新的分享”，不推断偷懒、失败或关系变差。
- 同步失败展示“内容尚未同步”；不能把本机 pending 当作他人已经看到。

## 账号入口（Goal A）

账号入口放在个人设置中，访客显示“本机访客”，不在首次启动弹登录。
登录流程：输入邮箱 → 请求验证码 → 输入验证码 →
确认身份 → 存在访客记录时选择迁移或暂不迁移。
成功登录不自动迁移、不自动组队。

| 场景 | 文案/动作 |
| --- | --- |
| 迁移确认 | “把本机记录关联到此账号并上传” / “暂不，保留为本机访客数据” |
| 错误验证码 | “验证码不正确，请重新输入” |
| 过期验证码 | “验证码已过期，请重新获取” |
| 请求限流 | “操作较频繁，请稍后再试”；按服务端允许的时间恢复按钮 |
| 网络失败 | “连接失败，请检查网络后重试”；保留本机记录 |
| 会话过期 | “登录已过期，本机修改仍保留，请重新登录后同步” |
| 有待同步操作时退出 | “有 N 项尚未上传，重新登录此账号前不会上传” |
| 退出完成 | 显示本机访客数据；不显示原账号记录，也不删除它们 |
| 同步冲突 | “两台设备的记录不一致”；展示双方并明确选择 |

日志不记录邮箱全文、验证码、token 或目标内容。界面的账号身份展示与调试日志分开。
