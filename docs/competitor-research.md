### 对本项目的具体建议

以下为待设计验证的建议，不是新功能已实现，也不改变产品方向和开发里程碑。
每项都对应[产品方向](product-direction.md)中的个人使用或自愿组队场景。

| 决定 | 实机依据 | 拟采用方式 | 场景 / 阶段 / 验收 |
| --- | --- | --- | --- |
| 借鉴少量模板与自定义并列 | HT04、LB02 | 提供阅读、运动等少量起点，可修改名称和规则；不预装大量目标 | 个人首次使用 / M1 / 模板与自定义均能不登录创建，模板不自动启用提醒或共享 |
| 借鉴简单重复设置，暂缓高级规则 | HT06、LB03 | M1 建议先做每天、指定星期；单次任务仍保留独立日期入口；每周任选次数、月度和自定义间隔待规则确认 | 个人习惯与单次任务 / M1 / 每天、周一三五、指定日期任务分别按所属日期出现；改规则不重算旧记录 |
| 借鉴可选记录，拒绝默认打断 | HT07、LB04、LB05 | 一次点击完成；不强制填目标量、日记或动态；备注/分享需主动打开 | 个人打卡、可选表达 / M1、M2 / 无文字即可完成；未完成也可走表达原型；私人文字不默认发布 |
| 借鉴图标与少量颜色提示 | HT05、LB03 | 用图标和轻量色彩帮助区分目标，标题、状态和按钮保持清晰；不复制品牌与素材 | 个人今天页 / M1 / 不靠颜色也能识别完成态；长标题、大字体不遮挡操作 |
| 借鉴当天与回顾分离的组织 | HT03；此前 Habitify 官方资料 | 今天处理当前任务，目标历史放详情或回顾；先验证日历，再考虑装饰性统计 | 个人执行与回顾 / M1 / 首页直接完成和撤销；历史能反映本人实际记录；竞品历史交互仍待测 |
| 精简首次使用与创建表单 | HT01、HT05、LB01–LB06 | 首次直接进入可用个人页；名称、简单规则、可选提醒优先；其余设置逐步展开 | 个人首次使用 / M1 / 不经问卷、承诺、购买或组队即可创建；拒绝通知仍可打卡 |

“每周任选几天”值得后续研究，但需要先定义周起始日、同一天多次记录及周末结算，
不能只因竞品已有入口就加入当前实现。健康同步、戒除模式、模板问卷、会员系统也不纳入 M1。
以上判断没有验证两款产品的成就机制或多人授权，不据此改变我们的非竞争和隐私原则。

## 参考对象

### Loop

证据等级 B，Android 下载已准备，待实测。

开发者说明其无需账号即可离线使用，支持单习惯提醒、灵活重复周期和数据导出。
这与我们的个人核心体验直接相关。
来源：[官方项目说明](https://github.com/iSoron/uhabits)。

- 借鉴目标：打开后直接记录，不让注册先挡住个人使用。
- 拟落地：今天页直接打卡；资料、历史和提醒不依赖云端。
- 不照搬：其习惯强度计算不是我们的首版必需能力，不引入复杂评分。
- 必须实测：首次建目标的必填项、打卡与撤销入口、修改提醒后旧提醒是否残留。

### Habitify

证据等级 B，Web 访问尝试未完成业务操作；未安装手机端。

手机端官方指南区分重复周期、目标量和可选提醒，并提供快速记录入口。
桌面与 Web 操作手册分别介绍当天列表和多日网格、撤销与记录历史。
来源：[手机入门指南](https://intercom.help/habitify-app/en/articles/11957562-get-started-with-habitify)、
[桌面与 Web 记录指南](https://intercom.help/habitify-app/en/articles/11203298-track-progress-of-habits-on-website-desktop-app)。

- 借鉴目标：当天执行与长期回顾使用不同视图，避免首页塞满统计。
- 拟落地：今天页使用单日列表；历史日历放在回顾或目标详情；常用打卡不进详情页。
- 不照搬：位置提醒、复杂计量、AI 建议不进入首版；不自动把未记录标成失败。
- 必须实测：手机端能否低成本撤销、创建流程的设置负担，以及免费范围对测试的影响。

### HabitShare

证据等级 B；用户已安装，本机版本 2.1.99，但尚未完成应用内实测。

官方说明默认习惯私密，并按朋友选择分享哪些习惯；它已经覆盖“不同的人共享各自目标”的一部分需求。
因此不能宣称我们首创“好友相互监督”。
来源：[HabitShare 官网](https://habitshareapp.com/)。

- 借鉴目标：共享范围由目标所有者决定，而不是加好友即开放所有数据。
- 拟落地：目标默认私密；共享确认显示接收的小组和会暴露的字段；支持撤销。
- 不照搬：不因为存在好友功能，就默认要求用户建立社交关系。
- 必须实测：双方目标不同的体验、撤销共享后的结果、目标备注与进度是否分别可见。
  界面显示不足以证明服务端权限安全，不能替竞品作安全保证。

### Streaks

证据等级 B，未安装或购买。

官网以少量目标、连续记录、指定执行日期和任务统计为主线。
来源：[Streaks 官网](https://streaks.app/)。

- 借鉴目标：突出当天少量可执行项目，完成反馈直接。
- 拟落地：目标标题和完成按钮有稳定位置，完成态不只依赖颜色，支持大字体。
- 不照搬：不把连续天数归零当作主要激励，也不以红色失败状态制造压力。
- 必须实测：手机端完成与撤销的操作成本、目标多时是否仍便于扫描。
  付费体验需要先获批准，不使用非官方破解包。

### HabitRix

证据等级 B，补充观察对象，未安装。

其官方帮助中心分别列出个人习惯、共享房间、成员可见内容和退出后的处理，
与我们的“个人为基础、小组可选”尤其接近。
它与 HabitShare 不是同一款产品，不混用名字或证据。
来源：[HabitRix 帮助中心](https://habitshare.app/help/)、
[产品说明](https://habitshare.app/)。

- 借鉴目标：清楚区分个人空间与共享空间，让加入和退出有可理解的结果。
- 拟落地：在共享前和退出前明确内容变化；个人目标不因退出小组而丢失。
- 不照搬：不采用共同强制任务、成员间连续天数比较或房间排名。
- 必须实测：房间是否允许完全不同的个人目标，退出后的历史与回复如何处理。

## 转化为我们的交互要求

下面保留资料研究阶段的设计建议。局部实机证据及其限制见上文，
不把这些要求整体视为已在竞品中验证。

| 编号 | 具体要求 | 对应参考 | 验收方法 |
| --- | --- | --- | --- |
| UX01 | 第一次打开即可开始本地使用，登录入口不阻塞 | Loop 的离线定位 | 新安装、不登录完成创建和打卡 |
| UX02 | 新建只突出名称、重复规则和可选提醒，其他设置逐步展开 | Habitify 的属性分组 | 默认流程不要求先设置分享或成就 |
| UX03 | 今天列表可直接打卡，撤销入口可发现 | Habitify 的快速记录与撤销 | 记录从今天页一次操作完成；撤销不超过两次操作，均为我们的目标值 |
| UX04 | 首页显示当天，历史单独查看 | Habitify 的分视图组织 | 不进入统计页也可处理全部当日任务 |
| UX05 | 提醒是个人设置，与组队邀请无关 | Loop、个人体验约定 | 不登录、不组队可设提醒；拒绝权限仍能记录 |
| UX06 | 共享确认显示接收范围，私人笔记不随进度发布 | HabitShare 的选择性共享 | 甲看到明确范围，乙只收到授权字段 |
| UX07 | 退出小组不损失个人工具价值 | HabitRix 的空间区分 | 退出后个人目标、历史和提醒保留 |
| UX08 | 反馈鼓励行动，不惩罚缺席 | Streaks 的聚焦感，加上本项目非竞争原则 | 检查未完成文案、成就和小组视图，无排名或关系分数 |

## 实测脚本

固定使用虚构目标：“阅读 10 分钟”“每周一三五散步”和“周五整理资料”。
产品不支持的类型记录为不支持，不用另一种类型假装通过。

| 编号 | 操作 | 必须记录 |
| --- | --- | --- |
| C01 | 新安装进入应用，不登录 | 平台、版本、引导页、是否能跳过登录 |
| C02 | 创建每天目标 | 必填项、点击次数、提示文案、是否请求通知 |
| C03 | 创建指定星期与单次任务 | 是否支持、入口、日期规则 |
| C04 | 完成并撤销 | 手势或按钮、反馈、误触恢复路径 |
| C05 | 设置一个近期提醒并离开前台 | 权限、实际到达时间和设备状态 |
| C06 | 修改时间、关闭、归档 | 旧提醒是否出现，不只看设置值 |
| C07 | 断网记录，关闭再打开 | 数据是否保留、有无误导性同步提示 |
| C08 | 查看历史和修改过去记录 | 日期展示、修正能力、连续天数变化 |
| C09 | 两个测试账号分享不同目标 | 默认可见范围、备注是否泄露 |
| C10 | 撤销共享和退出小组 | 另一端刷新后的可见性、本人记录是否保留 |
| C11 | 小屏和大字体 | 标题、按钮、表单是否可读可点 |

每条记录填写“通过、失败、不支持、受阻或未测”，附截图或操作记录。
提醒至少跨一次后台状态验证；长期可靠性需要多日观察，单次触发不代表稳定。
Android 的体验结果不能被写成已验证 iOS 通知行为。
