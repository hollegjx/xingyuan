## 所有者已确认的要求

2026-10-19 至 10-20 所有者确认如下；与旧版或旧实验冲突时以此为准：

- 后端负责调用 AI；用户记忆保存在手机本地，云端记忆存储以后可选、默认不启用。
- 通过对话让 AI 安排计划：可以是今天、明天，也可以是“这周”“下周”的多天多项任务。
- 任务可以带具体时间点和分钟数，也可以不带；由对话内容决定，用户在预览中可改。
- 除单次任务外，AI 也可以提出重复习惯（每天或指定星期）。
- 记忆参照豆包类产品：AI 在对话中自动记住有用信息，用户能看到、撤销、修改和删除。
- AI 创建的一批任务可以一键撤销。
- 目前只给两个人使用，各自私密，不做组队或互相查看；模型额度充足，不设费用上限。
- 使用 AI 不要求先完成邮箱登录或第二阶段 A 的云端账号。

## 做完后的使用效果

> 打开星愿进入“规划”，说：“这周每天晚上想读半小时书，周三加班就算了，周末整理房间。”
> AI 结合已记住的“工作日 19 点后有空”和这周已有的目标，给出一张按天分组的计划卡片：
> 尚未过去的工作日（除周三）19:30 读书 30 分钟；尚未过去的周末安排整理房间 60 分钟。
> 用户可以改名称、日期、时间、分钟，删除某项，选择不设时间，或一键为有时间的任务开提醒；
> 也可以在对话中明确要求“每周一二四五重复”，取得新的习惯提议。确认后任务出现在对应日期的目标列表中。
> 卡片显示实际创建数量和“撤销”；发现安排错了可以整批撤销。
> AI 回复下方出现本周三加班的记忆及撤销入口，约束在对应日期到期，不推断为每周固定加班。
> 记忆页可以查看、修改、删除全部记忆，也可以关闭自动记忆。
> 断网时 AI 不可用，已有目标、打卡、历史和个人提醒照常使用。

## 技术方案

| 层 | 建议方案 | 边界 |
| --- | --- | --- |
| iOS 客户端 | 保留 Flutter、Riverpod、Drift/SQLite | 不新增平台，不重写现有目标仓储 |
| 规划后端 | 已采用 `server/` 中的 Dart 服务；本机回环与临时 HTTPS 部署共用代码 | 共用 `packages/xingyuan_core`；Dart 路线已通过验证，不自动改用备选或接入 Supabase |
| 访问控制 | 每部手机一个设备访问凭证：服务器生成随机值，App 存入 iOS 钥匙串，服务器只存哈希，可单独吊销 | 不需要用户登录；第二阶段账号上线后再评估切换为账号凭证 |
| 模型 | 所有者指定的中转与 `gpt-6-luna` | 不静默换模型；密钥只在服务器环境或开发 Mac 钥匙串，不进 App 和 Git |
| 会话与记忆 | 只存手机本地，按本地身份隔离 | 后端每次接收本轮所需上下文，不保存正文 |
| 服务端记录 | 只记时间、request_id、设备标签、接口、状态码、耗时、token 用量及是否重试 | 不记聊天正文、记忆、目标内容或凭证明文 |

选择 Dart 正式服务的理由：只有两个用户；现有网关与模型适配已真实跑通；
服务端和客户端共用纯 Dart 包 `packages/xingyuan_core` 的协议与校验，避免两种语言维护两套规则；
本机未安装 Deno 和 Docker；也不依赖尚未通过的 G3 云端关卡。
最终 Goal D04 仅在 P1 证明 Dart 方案不可行时才允许考虑 Supabase Edge Function，且改用前须告知所有者；
服务器到期或网络问题不构成自动换架构的授权。按 D05/D06 迁移或等待所有者决定，不购买服务器或更换模型。

基本保护只保留防止程序故障的部分：请求大小上限、每部手机并发上限、超时、不自动无限重试。
按所有者决定，不设调用次数或费用上限。

## 功能设计

### 计划提议

- 一次提议可以包含单次任务和重复习惯，覆盖今天起最多 14 天（足够安排“这周”“下周”）。
- 单次任务字段：日期（必填，具体日历日）、名称、开始时间（可选）、分钟数（可选，5 至 480）。
- 重复习惯字段：名称、每天或指定星期、开始日期、开始时间（可选）、分钟数（可选）。
  P1 已按 Goal 5.1 采用兼容路径：习惯必须从创建当天开始，不支持未来开始日；过期草稿须显式改期。
- 每项提议最多 40 个单次任务、5 个习惯，同一天最多 12 项。这是最终 Goal 的当前规则，调整须由所有者确认。
- 是否带时间由对话决定：用户说“晚上”“19 点”时排具体时间，只说“这周读完一本书”时可以不排。
  用户也可以通过记忆或在预览中选择“不设具体时间”。
- “这周”“下周”按星期一为周起点，由客户端提供的当前日期和时区换算成具体日期；
  含义不明确时 AI 先追问，不自行猜测。
- 一轮回复最多一份计划提议；普通聊天或信息不足时只回复或追问，不强制生成计划。

### 预览、确认与撤销

- 预览按日期分组，显示星期、时间和分钟数；可以改名称、日期、时间、分钟数，编辑习惯星期，
  删除某项或清除全部时间。早期概览还设想“把一组同名任务直接转为习惯”，当前没有这一转换按钮；
  该草案与最终 Goal 列出的字段编辑分开记录，不以对话中新建习惯提议冒充已实现的预览转换。
- 与已有目标同日同名、或与已有带时间目标时间重叠时，在预览中标出，由用户决定保留或删除。
- 提醒默认关闭。预览提供“为有时间的任务开启提醒”，提醒时间默认等于开始时间；
  首次开启时才请求通知权限，拒绝不影响创建。受现有 64 个提醒名额规则约束并显示覆盖情况。
- 确认后在同一事务内创建全部任务、提醒设置与回执，失败整体回滚。
  同一提议重复确认返回原结果；已确认的提议换内容重放则拒绝。
- 确认时若部分日期已经过去，这些项标为“已过期”，用户改日期或删除后才能创建，不悄悄改成今天。
- 撤销：先列出将删除/保留的项，由用户确认；没有任何打卡记录的本批任务连同待上传操作在事务中删除，
  提交后取消系统提醒。有过打卡记录（包括后来撤销打卡）的任务保留并列出；已上传的目标改为归档，
  不发明服务端删除协议。重复撤销不产生额外变化，整批撤销本身不能恢复。
  这是对“M1 不提供永久删除”规则的有限例外，只适用于 AI 创建的批次。

### 记忆

参照豆包类产品的做法，分短期和长期两层，全部保存在手机本地：

- **短期记忆**：当前会话的最近若干轮原文。会话变长时，由后端对较早内容生成摘要，
  摘要保存在本地会话中，可以查看；不会悄悄丢掉用户刚说过的约束。
- **长期记忆**：AI 每轮可以附带最多 5 条记忆操作（新增、更新、删除），客户端自动保存，
  并在该条回复下显示“已记住：…… · 撤销”。用户说“忘掉……”时删除对应条目。
- 记什么：作息与空闲时间、偏好、长期目标与背景、阶段性约束（可带到期日，如“这周三加班”）。
  不记密码、证件号、账号凭据和与规划无关的他人隐私；一次性闲聊不进长期记忆。
- 自动记忆默认开启，可在设置中关闭；关闭后只在用户明确说“记住”时保存。
- 按执行 Goal 的规则发送有效记忆：每身份最多 200 条、每条最多 200 字，置顶优先；
  不采用早期草案的 2,000 字关键词截取。整体请求超过 64 KiB 时明确提示新开会话或关闭分类，
  不悄悄删除记忆。第一版不引入向量检索。
- 记忆页按类别列出全部条目及来源会话和时间，支持修改、删除、置顶、清空。
  删除记忆不会删除来源聊天；删除会话也不会删除已确认的记忆，界面说明两者区别。
- 原实验保存的“本机偏好”迁移为长期记忆。原“AI 当日规划”表单页被对话页取代，
  原有草稿和回执保留，用于幂等重放和历史追溯。
  所有者 2026-10-20 批准超过 200 字时按序拆为多条，每条最多 200 个用户可见字符，
  不拆组合字符、不裁剪空格/换行或改写，拼接完整还原原文，旧表完整保留。真机迁移另行验收。

### 发送范围与授权

2026-11-02 C80所有者决定优先于以下历史规则：新持续聊天需授权版本4明确同意。
总开关开启后，助手可按需读取本人[今天-6,今天]共7日期已保存的打卡、随手记、日记文字，
无需逐日确认；记录衍生的聊天和摘要可跨轮使用。读取后显示日期/类型/条数及实际状态。
照片、附件、位置、未保存草稿、已删除记录、其他身份和全量历史均不发送。
当前输入、预算内最近聊天和模型维护摘要发送到既有后端/中转/模型；后端不新增正文日志，
摘要只在本机保存。模型/额度/配置不变。模型摘要最多1200字，不增加独立摘要调用。
关闭总开关后停止读取；曾读取非空记录的会话保守排除全部旧聊天及摘要，仅发送新输入，
来源于会话的自动记忆也排除；取消在途结果，旧服务/v1回退不发送记录衍生上下文。
清空摘要同时停止发送此前聊天，使在途结果失效；完整聊天和业务记录保留在本地，
旧独立记忆条目仍由原记忆管理入口管理。重新开启总开关允许再次使用保存的上下文。
日程/日记仅出待确认卡片，确认前不保存、不覆盖、不分享。界面与授权文案由统筹交付。
旧会话/旧客户端保留以下原契约；不会自动并入新持续聊天。


- 首次使用 AI 时一次性说明并确认：数据发往星愿后端、所有者的中转和 `gpt-6-luna`；
  会发送当前对话、相关记忆、计划日期范围内的已有目标与近 14 天完成情况；后端不保存正文。
  确认前零网络请求。之后每句话不再弹窗确认。
- 设置中可分别关闭“已有目标与安排”“近期完成情况”“记忆”三类上下文，关闭后不再发送。
- 每条用户消息保存不含凭证的实际请求体，可展开“本轮发送内容”。旧失败请求保留，重试使用新 id。
- 不发送私密笔记、归档目标详情、设备标识或其他身份的数据；中转是否留存请求另行说明。
- 退出、切换本地身份或请求进行中切换身份后，晚到的回复不得进入新身份的对话、记忆或计划。

### 接口

以下名称按执行 Goal 与已实现的后端统一；客户端页面已接入，完整验收状态见账本：

| 接口 | 执行位置 | 输入与输出 |
| --- | --- | --- |
| `POST /v1/turn` | 后端 | 协议版本、请求 id、当前日期/时间/时区、会话上下文、获准的记忆与目标摘要；返回回复文本、可选计划提议、可选记忆操作 |
| `POST /v1/summarize` | 后端 | 较早的会话内容与旧摘要；返回不超过 1,500 字的摘要文本 |
| `applyPlan` / `undoPlan` | 手机本地 | 已确认的提议 id、版本与任务；原子创建或整批撤销并返回结果 |
| `applyMemoryOps` | 手机本地 | 校验后的记忆操作；只允许修改本轮发送过的记忆条目 |

服务端自己定义系统指令与工具清单，不接受客户端历史中伪造的高权限指令，
不把模型输出的任何 id 当鉴权依据；模型输出一律作为不可信数据校验。
第一版不做自主循环、联网搜索、任意代码执行，也不修改或删除用户已有的目标。
先完成非流式回合，等待时显示进度；流式文字作为后续体验项，半截工具输出永不执行。
界面的“已创建”由手机实际写入回执决定，不凭模型的一句回复决定。

### 数据模型

- 在 `goal_schedules` 增加可选的开始时间（当天分钟数）和预计分钟数，随 `effective_day`
  版本化，修改时间不改写历史含义；schema 升到 v5，v1 至 v4 原数据保留且这两个字段为空。
- 今天页、管理页和历史页显示时间与分钟数，有时间的任务按时间排序；手动创建和编辑也能设置。
- 对话、会话摘要、长期记忆分表保存，按本地身份隔离，不进入云同步 outbox。
- 同步目标文档加入时间/分钟字段，按已有规则递增协议版本并更新 [同步设计](sync-design.md)。
  撤销删除尚未上传的本地操作；已上传目标走已有归档语义，不新增服务端删除协议。
  云端仍未接入，本任务不越过第二阶段 A 的 G3。

## 验收清单

以下 AC 编号仅用于概览，执行与最终完成判定使用 Goal 的 A01-A22 全矩阵和第 11 章通过线；
不得将此表较短的描述作为减项或降低真实模型/设备证据要求的依据。

| 编号 | 可重复检查 | 证据要求 |
| --- | --- | --- |
| AC01 对话 | 普通聊天零目标写入；信息不足先追问；三轮内更正可用时间后，新提议采用新约束 | 自动测试、真实模型样例 |
| AC02 多日计划 | “安排这周”“下周一到周三”生成正确的具体日期，按天分组，符合数量范围 | 时钟注入测试、真实模型样例 |
| AC03 时间与分钟 | 带时间、不带时间、只带分钟三种任务均可预览、编辑、创建和显示；手动目标同样可用 | 仓储与 UI 测试、模拟器 |
| AC04 习惯 | “每周一三五 7 点跑步”创建为对应星期的习惯，打卡规则与手动习惯一致 | 仓储测试、模拟器 |
| AC05 确认 | 无确认零写入；全部成功或全部回滚；重复提交、重启重放不重复创建 | 仓储事务、UI、两进程探针 |
| AC06 撤销 | 未打卡任务连同提醒和待上传操作一起删除；已打卡任务保留并列出；重复撤销无副作用 | 仓储测试、通知与 outbox 检查 |
| AC07 冲突 | 已有同日同名或时间重叠的目标在预览中标出，仅提示不阻止；模型避开或说明冲突按 C10 与第 11 章评测 | 自动测试、真实模型评测 |
| AC08 记忆 | 自动记住的内容带撤销；新会话可用；“忘掉”生效；关闭自动记忆后不再自动保存；过期记忆不发送；全部有效记忆按规则发送，整体超过 64 KiB 明确失败，不截取记忆 | SQLite 重启测试、请求字段检查 |
| AC09 隐私 | 首次授权前零请求；关闭的类别不发送；“本轮发送内容”与实际请求一致；切换身份后晚到结果隔离；日志无正文和凭证 | 客户端/后端负向测试 |
| AC10 日期 | 今天、明天、本周、下周、跨午夜过期项、时区变化；预览与实际目标日期一致，旧记录不改动 | 时钟注入、模拟器、真机分别报告 |
| AC11 中断 | 断网、超时、取消等待、截断响应均不误报成功，不自动无限重试 | 故障注入、真实网络检查 |
| AC12 访问控制 | 有效设备凭证可调用；缺失、错误、已吊销凭证在调用模型前被拒 | 直接请求部署服务，不用 UI 隐藏替代 |
| AC13 回归 | 私密默认、提醒默认关闭；原目标、历史、提醒不受影响；不用 AI 仍可手动记录；v4 升 v5 原位升级保留数据 | 全量本地回归、迁移测试、真机原位升级 |
| AC14 两部手机独立使用 | 关闭 Mac 后，两部 iPhone 分别完成对话、计划创建与撤销；双方数据互不可见 | 手机 Wi-Fi/移动网络，与两位用户配合验证 |

真机操作需要所有者解锁和配合网络切换；不卸载 App、不清库、不上传真实历史作为测试数据。
代码格式、静态分析、生成一致性与测试遵循[开发说明](development.md)。后端增加独立的
格式、静态分析、单元与协议检查；CI 不放模型密钥；真实推理和设备验收单独记录，跳过不算通过。

## 暂不做

- AI 修改、改期或删除用户已有的目标（交付点 B 后的首个扩展候选）。
- 云端记忆同步、向量检索、语音和图片、联网搜索、自动打卡、服务器主动推送。
- 两人之间的分享、互相查看或互动（属于小组陪伴 Goal B），以及排名、新平台、AI 收费功能。

这些不作为交付 A/B 的隐藏前置，也不因为引入 AI 放弃原有的个人离线功能。
本计划不依赖第二阶段 A（账号与云同步），两者先后由所有者决定；
数据模型的变化需要同步更新第二阶段的同步设计。
